# 차단기 이후부터 터널 테스트 (8단계 시작)

**차단기에 막혀 기다리던 위치에서, 차단기를 완전히 열어 둔 상태로 시작한다.** 아래 순서로 센서 → 기록 → 8단계 주행을 실행한다. 종료는 제어기 정지 → 실제 정지 확인 → 기록 저장 순서다.

현재 설정은 외측 **1,820mm·벽 2mm·출입구 300mm 연습장**용 `tunnel.real.yaml`이다. 새 YAML을 만들거나 시작 단계 인자를 직접 적을 필요는 없다. 대회용 지도는 아직 미완성이므로 이 안내는 연습장에 적용한다.

## 1. 로봇 배치

- 차단기가 닫혀 있었다면 정차했을 지점에 놓고, **로봇 정면을 차선 진행 방향**으로 맞춘다. 카메라에 바닥의 흰색·노란색 차선이 보여야 한다.
- 차단기는 완전히 올려 통로에서 벗어나게 고정한다. **8단계는 차단기 열림을 확인하거나 기다리지 않는다.** 닫힌 차단기 앞에서 실행하지 않는다.
- 차단기에서 터널 입구까지 차선과 통로를 확보한다. 8·8.5단계에는 터널의 장애물 경로 계획이 아직 시작되지 않는다. 출구 바깥 약 200mm와 이어지는 차선도 비워 둔다.
- 이번 시작 위치는 터널 입구의 바퀴축 140mm 배치 지점이 아니다. 터널 단계에 도착하면 정지한 채 LiDAR로 벽과 시작 위치를 확인한다. 입구와 전혀 다른 위치에서 차선이 끊기면 이 절차가 진행되지 않을 수 있다.

주행은 **8 차선 추종 → 차선 10프레임 연속 소실 → 8.5 약 15cm 추가 직진 → 9 벽 위치 확인·초기 직진 → 10 경로 계획·추종 → 출구 정지 → 11 차선 주행** 순서다. 8.5단계는 차선이 끊길 때 방향을 유지하며 0.06m/s로 2.5초 전진한다. 입구에서 별도 정렬 회전은 하지 않는다.

출구에서는 감속하고 `WAIT_STOP`에서 새 odom으로 정지를 확인한 뒤 11단계로 넘어간다. 차선 3프레임 확인이나 고정 시간 대기는 없다. 전환 후 첫 영상에서 한쪽 선만 인식돼도 기존 차선 추종을 시작한다. 영상이 없거나 처음부터 선을 전혀 인식하지 못하면 정지를 유지한다.

**터널 완료 후에도 11단계 차선 주행이 계속된다.** 자동 종료되지 않으므로 정지용 터미널을 먼저 준비한다. 터널 속도 설정은 8·8.5·11단계 차선 주행 속도의 공통 상한이 아니다.

## 2. 각 터미널의 공통 준비

SSH 터미널 4개를 열고 **각 창에서** 아래 두 줄을 한 번씩 실행한다. 이후 명령은 모두 이 폴더에서 실행한다.

```bash
cd /home/sj/ParkCars/TB-tunnel-nuc
source scripts/nuc_env.sh
```

## 3. 터미널 1: 센서 시작

```bash
bash scripts/nuc_sensors.sh --mounts
```

카메라·LiDAR·OpenCR와 장착 TF를 실행한다. 이 창은 열어 둔다. 센서가 이미 실행 중이면 중복 실행하지 않으며, 다른 자율주행·teleop도 함께 켜지 않는다.

## 4. 터미널 2: 기록 시작

```bash
python3 scripts/nuc_trial.py record
```

`Recording: ...`가 나오면 기록이 시작된 것이다. 창을 열어 둔다. 실제 카메라·LiDAR·odom·cmd_vel·TF·ROS 로그와 모터 상태, 사용한 YAML·지도·Git 커밋·소스·실행 로그를 함께 보관한다.

코드나 설정을 바꿨다면 이전 기록을 종료하고 **새 `record`**를 시작한다. 주행 시작 시 기록과 현재 설정·소스가 일치하는지 확인한다.

## 5. 터미널 3: 8단계부터 주행 시작

**이 명령을 실행하면 실제 로봇이 움직인다.** 차단기 열림과 로봇 배치를 확인한 뒤 실행한다.

```bash
python3 scripts/nuc_trial.py start8
```

약 9초 동안 센서·측정 시각 TF·조종 입력·다른 `/cmd_vel` 발행자·기록 상태를 검사한다. 이어 모터 토크 활성화와 새 OpenCR 응답을 확인하고 `/tb_controller`를 **8단계·실물 YAML·normal**로 시작한다. 검사 실패 시 주행을 시작하지 않는다. 별도 토크 명령은 필요 없다.

주행 명령은 일반 SSH 터미널에서 실행할 수 있다. 차선 디버그 창은 기본으로 꺼져 있어 X11이나 RViz를 켤 필요는 없다.

9단계에서 `LOCALIZING`이 보이면 벽 위치 확인 중이므로 로봇을 옮기지 않는다. `wall alignment ...` 뒤 초기 직진이 시작된다. 계속 기다리면 아래 방법으로 `controller.log`의 `TUNNEL:` 사유를 확인한다. 위치를 확인하지 못했다고 임의로 로봇을 앞으로 밀거나 시간 제한부터 늘리지 않는다.

8·11단계 차선 추종은 원격 `e0b970f`의 `codes/final_codes/speedup.py` 제어를 반영했다. 기본 전진 속도는 **약 0.105m/s**, 회전 명령 상한은 **0.629rad/s**다. 실행 로그에 `Lane tracking: upstream speedup e0b970f`가 표시된다.

터널 초기 직진 상한은 **0.30m/s**, 경로 순항 상한은 **0.32m/s**다. 실행 시 `normal`은 터널 설정을 뜻한다. 터널 속도는 `codes/stepbystep/tunnel.real.yaml`의 `entry.cruise_velocity`와 `control.cruise_velocity`에 있다.

초기 직진의 장애물 정지 간격은 앞범퍼 기준 **35cm**이며 `entry.obstacle_clearance`로 설정한다. 35cm는 제어 목표이며 실제 정지 간격은 센서 검출 시점과 구동계 응답에 따라 달라질 수 있다.

## 6. 터미널 4: 정지하고 기록 저장

PC와 센서를 켜 둔 채 먼저 실행한다.

```bash
python3 scripts/nuc_trial.py stop
```

제어기를 종료하고 기존 OpenCR에 모터 토크 해제를 요청한다. 새 `torque=false` 응답은 드라이버가 보고한 상태다. **로봇이 실제로 멈춘 것을 확인한 뒤** 기록을 종료한다.

```bash
python3 scripts/nuc_trial.py stop-record
```

**`Bag finalized: .../sensors.bag`가 나오면 저장이 완료됐다.** 그다음 센서 창에서 Ctrl+C로 종료한다. PC를 끄려면 운영체제를 정상 종료한 뒤 전원 스위치를 사용한다.

정지 명령이 실패하거나 계속 움직이면 실제 구동 전원을 차단한다. PC 전원 스위치만으로 모터 정지를 보장하지 않는다. `/step=0`이나 `/cmd_vel`에 0을 한 번 보내는 것은 지속 정지 방법이 아니다. 주행 창에서 Ctrl+C를 눌렀어도 위 `stop` → 실제 정지 확인 → `stop-record` 순서를 따른다.

다음 시험은 같은 배치에서 새 `record` 후 `start8`을 실행한다. 센서가 계속 켜져 있으면 다시 시작할 필요 없다.

## 기록과 오류 확인

기록은 `records/날짜_시각_마이크로초_KST/`에 저장된다. 최신 시험의 위치와 실행 로그를 확인한다.

```bash
TB_TRIAL_DIR=$(cat records/current_trial.txt)
tail -n 30 "$TB_TRIAL_DIR/controller.log"
```

저장된 기록 확인:

```bash
rosbag info "$TB_TRIAL_DIR/sensors.bag"
```

시작 전 연결 오류는 같은 폴더의 `prestart_diagnostics.json`·`prestart_diagnostics.log`, 기록 오류는 `rosbag.log`에 남는다. `.bag.active`가 남으면 정상 저장이 끝나지 않은 것이므로 파일을 보존한다. 내부 상태·사유는 로그에 남지만 계획 경로와 costmap 전체가 자동 저장되는 것은 아니다.

## Windows에서 RViz 보기 (선택)

MobaXterm에서 `sj@192.168.0.3`으로 SSH 연결하고 **Advanced SSH settings → X11-Forwarding**을 켠다. 새 연결 창에서 위 공통 준비를 한 뒤 실행한다.

```bash
bash scripts/nuc_rviz.sh
```

일반 SSH만으로는 창이 뜨지 않는다. 화면이 안 열리면 `echo "$DISPLAY"`가 `localhost:10.0` 같은 값인지 확인하고, 비어 있거나 `:0`이면 X11 전달을 켜고 재접속한다. 센서는 별도 창에서 실행 중이어야 한다.

RViz는 원본 LiDAR 점군·카메라·odom·TF를 표시한다. 계획 경로·costmap은 현재 표시되지 않는다. RViz를 여는 명령 자체는 주행을 시작하지 않는다.

## 이번 테스트의 범위

8단계부터의 가상 검사는 합성 차선 영상·빈 터널·이상적인 운동 모델에서 단계 전환과 터널 주행을 확인한 것이다. 실제 기록 영상 재생에서는 반영된 차선 추종이 최신 원격 코드와 같은 명령을 내는지 확인했다. 원격 코드의 색 검출 범위도 기존과 같아, 밝게 찍힌 노란 차선을 놓치는 문제는 남아 있다. 실제 곡선 추종 성공과 장애물이 있는 전체 구간, odom 거리 스케일·제동 성능은 실물 주행으로 확인해야 한다.

현재 장애물 필터는 LiDAR 높이보다 높은 병 연습 조건에 맞춘 수평 ±0.5°·반사 강도 2 이상이다. 낮은 물체와 위쪽 돌출물, 약한 반사 물체를 놓칠 수 있다. 초기 직진의 전방 장애물 판단 범위는 차체 중심에서 왼쪽 100.3mm(차체 끝 + 10mm), 오른쪽 85mm(차체 끝보다 5.3mm 안쪽)다. 왼쪽 값은 `entry.obstacle_half_width`, 오른쪽 값은 `entry.obstacle_right_width`로 설정한다. 지도·경로에는 차체 크기와 10mm 여유를 적용한다.
