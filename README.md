# TB — tunnel port

`yee-ri/TB`의 `b683f7c`에서 분리한 터널 이식본. 다른 미션은 TB 코드를 사용한다.

## 분리된 Gazebo 시험

`codex/tunnel-port`는 이식 기준본, `codex/tunnel-gazebo`는 별도 작업 폴더의 시뮬레이션 브랜치다.
`main`에는 병합하지 않는다. 실행 명령은 [DOCKER_NOETIC.md](DOCKER_NOETIC.md)를 참고한다.

- 기존 custom robot·경기장·빌드 결과를 `/workspace`에 읽기 전용으로 연결한다.
- 전용 컨테이너 내부에서만 ROS를 실행하며, TB 노드 하나만 `/cmd_vel`을 발행한다.
- 터널 입구에서 step 9로 시작한다. 공식 시작점 전체 주행이 아니다.
- Gazebo `LaserScan`을 TB 노드가 직접 받는다. 기본 실물 입력은 기존 `PointCloud2`다.
- Gazebo는 원본 통합 설정과 같은 world odometry + EKF를 사용한다. 실물 위치추정 검증이 아니다.
- 전체 코스는 입구 기준 정합과 다른 TB 미션의 센서 연결도 필요하다. 현재 Gazebo RGB 카메라는 TB 차단봉용 깊이 영상을 제공하지 않는다.

초기 연결본 `3d7756d`는 센서 연결은 됐지만 미관측 격자 검사 때문에 입구에서 정지했다.
현재는 진입을 방향 유지 직진으로 분리하고, 실제 LaserScan의 빈 공간 정보도 보존한다.

## 실행

ROS Noetic, 정상 빌드한 센서 드라이버 작업공간, `numpy`, `PyYAML`, OpenCV가 필요하다.
저장소에 들어 있는 과거 `catkin_ws/devel`의 절대경로 설정은 그대로 사용하지 않는다.

```bash
# 터미널 1: 카메라·OpenCR·Mid-360 시작 (센서 작업공간을 먼저 source)
./start_robot.sh
```

```bash
# 터미널 2: 공식 미션 순서로 시작
cd codes/stepbystep
python3 try_maze.py _start_step:=0
```

```bash
# 터널 진입 기준 자세에서만 단독 시험. 전체 코스 검증이 아님.
python3 try_maze.py _start_step:=9
```

설정은 `codes/stepbystep/tunnel.yaml`. 다른 설정은 `_tunnel_config:=/절대경로/설정.yaml`로 선택한다.
기본 `normal`은 내부 순항 0.075m/s·직진 진입 상한 0.04m/s다.
Gazebo의 선택형 `fast`는 원본 FAST 설정으로 진입·내부 상한 0.32m/s를 사용한다.
진입은 초기 속도에서 가속하고 남은 거리로 감속한다. 정상 목표 도착 시에도 가감속 제한을 적용한다.
FAST는 실물 검증 설정이 아니다. 선택 명령은 `DOCKER_NOETIC.md`를 참고한다.

## 이식 범위

- TB의 `/odom`, 영상 판단, 미션 순서와 단일 `/cmd_vel` 발행자를 유지한다.
- step 9: 입구 방향을 유지해 직진한다. 설정 거리(0.92m) 또는 차폭 안 전방 장애물 앞 여유(0.30m)에서 멈춘다.
- step 10: 측정 속도가 멈추면 Hybrid A*로 출구 안쪽의 방향 정렬 지점까지 탐색한다. 원본 출구 연결곡선을 붙여 전체 충돌검사를 통과한 하나의 경로를 odom으로 추종한다. 중간 지점에서 정지하지 않는다.
- 출구 위치·방향과 새 카메라 차선 검출이 확인되면 step 11의 기존 차선 제어로 돌아간다.
- 지도 갱신만으로 경로를 버리지 않는다. 남은 경로의 실제 장애물 충돌은 재탐색하고, 실제 제동 영역 충돌이나 센서 끊김에는 정지한다.
- 진입 전에 격자·90도 회전 가능 여부를 검사하지 않는다. 미관측 칸만으로 출발과 추종을 막지 않는다.
- LiDAR 취득 시각의 TF를 사용한다. LaserScan의 실제 무반사(+inf)는 빈 공간으로 전달하며, PointCloud에서 점이 없는 방향은 NaN으로 남긴다.
- 기본 설정은 원본과 같은 2회 검출·2회 빈 공간 관측과 기존 표면 주변 30mm 삭제 보호를 사용한다. 탐색 목표 방향 허용오차는 8°다. FAST는 원본 FAST의 삭제 보호 0mm·목표 방향 10°·출구 영역을 사용하며 차체 크기와 패딩은 바꾸지 않는다.
- 원본 고정 벽 지도와 벽 주변 중복 LiDAR 검출 제외 처리를 사용한다. 인접 측정으로 확인된 장애물 표면은 기존 라이브러리의 5mm 형상을 전달한다. 고립 측정점은 2cm 칸으로 유지한다.
- 장애물 주변 60mm 영역은 원본과 같은 경로 선택 비용으로 사용한다. 통행 금지 영역이 아니며, 실제 장애물 충돌 검사와 구분한다.
- 현재 차체와 지도 장애물이 겹치면 기존 경로를 유지하고 정지한다. 관측이 갱신되면 같은 충돌검사로 다시 판단한다. 한 번의 탐색 실패를 영구 실패로 바꾸지 않고 원본의 0.5초 재탐색 간격을 적용한다.
- 지도 내용이 실제로 달라졌을 때만 경로를 재검사한다. 탐색 중 출발 자세가 움직였다면 원본 허용오차로 결과를 거절한다.

`tunnel/planner.py`, `costmap.py`는 원본 프로젝트에서 이식했다. 사용하지 않는 격자 기반 진입 선택기는 제거했다.
`tracking.py`는 원본의 추종·속도 제한과 출구 연결곡선에 필요한 기하 함수만 추출했다. `mission.py`가 이들을 TB 입력에 연결한다.
원본의 AMCL·미션 관리자·별도 터널 ROS 노드·다른 미션용 라이브러리는 필요하지 않다.
대체된 `maze_navigation.py`는 제거했으며 이전 내용은 Git의 원본 커밋에 남아 있다.

## 좌표와 실물 적용 전 확인

기본 목표는 사용자가 지정한 **원본 Gazebo 터널 출구**다.

| 기준 | 원본 map 좌표 | 이식본의 진입 기준 상대 좌표 |
| --- | --- | --- |
| 진입 자세 | `(-1.7475895, 0.140, -90°)` | `(0, 0, 0°)` |
| 터널 밖 출구 | `(0.200, -1.748373, 0°)` | `(1.888373, 1.9475895, 90°)` |

이식본은 시작 odom을 고정하므로 **step 9가 이 진입 자세에서 시작한다는 전제**가 있다.
TB의 카메라 차선 소실 조건은 이 자세와의 일치를 보증하지 않는다.
이식본에는 원본의 LiDAR 입구 정렬·AMCL 정렬을 넣지 않았다.
고정 벽 지도는 `codes/stepbystep/maps/autorace_gazebo.pgm` 원본 복사본을 위 진입 기준으로 회전·이동해 사용한다. 원통 장애물은 지도에 미리 넣지 않고 LiDAR로 검출한다.
계획과 제동 검사는 고정 벽과 LiDAR 장애물에 적용한다. 미관측 공간을 실제 장애물로 간주하지 않는다.

차체 수치는 원본 custom robot의 비대칭 직사각형 기준이다. TB 저장소만으로는 실제 차체의 앞·뒤·폭을 확인할 수 없다.
실물 실행 전 footprint, 센서 TF, 고정 벽 지도와 입구 기준 자세, 출구 위치를 맞춰야 한다.

원본과 달리 TB의 단일 발행자·직선 진입·출구 정지 후 카메라 확인을 유지한다.
원본의 입구 LiDAR 정합, 별도 차선 컨트롤러 서비스 인계, 이동 중 검증된 차선 경로 확인은 TB에 그대로 복사하지 않았다.
장애물 여유 비용은 경로 선택에 쓰되, 비용만 증가했다고 주행 경로를 버리지는 않는다.
임의 시간 경과만으로 터널 미션을 실패 종료하는 제한은 추가하지 않았다.

기본 `normal`은 유지했다. 모든 시간은 시뮬레이션 시간이며, 접촉 센서·실물·공식 시작점 통합 검증은 아니다.
